O-RAN Open Fronthaul S-Plane — Software Testbed

Configuration, Setup and Standards Reference  ·  Revised 2026-09-17 (supersedes the prior 81-run revision)

Document scope. Every hardware and software configuration used by the testbed, each traced to the standard or reference implementation that fixes it. No value is assumed — all were read back from the running system or from the cited standard.

Telecom profile. ITU-T G.8275.1 — PTP telecom profile for phase/time distribution with full timing support. Selected because O-RAN sync configs LLS-C1/C2/C3 distribute timing through the network, and because the real TIMESAFE hardware captures used for comparison run domain 24 (G.8275.1) on all 344,630 PTP packets across the six captures.

Frozen state. 18 artefacts SHA-256 hashed; verify_frozen.sh refuses to run if any changed and was passed before every admissible run.

Validation result (current). 132 admissible runs across 12 randomised replicates. Attack sensitivity 1.000 [0.940, 1.000] (n=60); benign specificity 0.800 [0.682, 0.882] (n=60) — 1.000 [0.926, 1.000] (n=48) once the single known schema limitation B_bc_replacement is excluded, which accounts for all 12 false positives; honest abstention 12/12; attack attribution 0.817 [0.701, 0.894]. Zero infrastructure failures.

Corrections in this revision (all pre-freeze, all verified). (1) Added dataset_comparison G.8275.x — it was missing, so linuxptp had been running the IEEE-1588 default BMCA rather than the G.8275.1 alternate BMCA. A capture cannot reveal this (the BMCA algorithm is not a wire field), so the earlier "verified by parsing its own capture" could not have caught it. (2) Removed path_trace_enabled 1 — real TIMESAFE captures carry zero TLVs in all 344,630 PTP packets of the six captures, so leaving PATH_TRACE on makes its presence a perfect testbed-vs-TIMESAFE separator (a provenance leak). (3) Added a per-node config generator (run/mkcfg.sh); option scoping verified against linuxptp v4.0 config.c. (4) A 4th provenance leak was logged: minor_version_ptp (testbed 4.0 = 1, real = 0) — a compile-time constant, apparatus-only, excluded from any join.

Binary attack detection 60/60 (TP=60, FN=0). All 12 specificity false positives are the single B_bc_replacement schema limitation. Attribution confusion A1→A3 (×4) and A8→A3 (×7) is the documented re-parenting effect (rogue master/BC insertion causes real sequenceId restarts, caught by the A3 clause first); it does not change the binary ATTACK verdict. Cross-domain: the frozen rule, applied unchanged to six real TIMESAFE hardware captures it never saw, classified 6 of 6 as ATTACK; 5 of 6 on standards/protocol rules alone (3 by Announce-field legality, 2 by IEEE 1588 cl.11.3 sequenceId monotonicity). The remaining one is a healthy-looking spoof with fully conformant fields and needs the provisioned allow-list.
